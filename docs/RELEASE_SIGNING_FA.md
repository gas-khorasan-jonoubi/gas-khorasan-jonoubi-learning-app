# راهنمای آماده‌سازی امضای امن نسخه انتشار

این برنامه باید برای تمام نسخه‌های انتشار با **یک keystore ثابت** امضا شود. تعویض این فایل در آینده می‌تواند نصب به‌روزرسانی روی نسخه قبلی را مختل کند.

## مرجع keystore در Codemagic

در Codemagic از مسیر زیر یک Android keystore ثبت کنید:

1. Team settings
2. بخش Code signing identities
3. زبانه Android keystores
4. فایل keystore را بارگذاری کنید.
5. برای Reference name دقیقاً این نام را انتخاب کنید:

`danestani_gaz_release`

در `codemagic.yaml` همین مرجع برای workflow انتشار استفاده شده است.

## نسخه پشتیبان

فایل اصلی keystore را پیش از بارگذاری، در دو محل امن و مستقل نگهداری کنید. Codemagic پس از بارگذاری امکان دانلود دوباره فایل keystore را نمی‌دهد. فایل و رمزهای آن را در مخزن GitHub، پیام عمومی یا فایل پروژه قرار ندهید.

## مقادیر لازم در زمان build

Codemagic از keystore ثبت‌شده این متغیرها را در محیط build فراهم می‌کند:

- `CM_KEYSTORE_PATH`
- `CM_KEYSTORE_PASSWORD`
- `CM_KEY_ALIAS`
- `CM_KEY_PASSWORD`

اسکریپت `tool/configure_bazaar_android.py` فقط نام متغیرها را در Gradle قرار می‌دهد؛ مقدار رمزها یا مسیر محرمانه را داخل فایل Gradle نمی‌نویسد.

اگر keystore ثبت نشده باشد یا هرکدام از متغیرها ناقص باشد، مرحله اعتبارسنجی انتشار باید متوقف شود. این رفتار عمدی است تا APK با کلید آزمایشی یا امضای debug منتشر نشود.

## دو شناسه دیگر کافه‌بازار

در Codemagic باید این دو مقدار واقعی نیز ثبت شوند:

- `BAZAAR_APPLICATION_ID`: شناسه بسته اندروید که در پنل کافه‌بازار برای همین برنامه ثبت شده است.
- `BAZAAR_LIFETIME_PRODUCT_ID`: شناسه محصول خرید یک‌باره و دائمی برنامه.

این شناسه‌ها باید از پنل واقعی کافه‌بازار خوانده شوند؛ در سورس پروژه مقدار حدسی قرار داده نشده است.

## کنترل‌های پیش از انتشار

- بررسی نسخه Flutter/Dart و حداقل Android API 24
- بررسی SDK کافه‌بازار و وابستگی‌های native
- کامپایل Kotlin میزبان release بدون بسته‌بندی APK
- اجرای `flutter analyze` و `flutter test`
- پس از اجازه صریح ساخت APK: ساخت release با keystore ثابت و بررسی اینکه SDK فروشگاه دیگری وارد artifact نشده باشد
- آزمایش خرید و بازیابی با حساب آزمایشی کافه‌بازار و دستگاه Android واقعی

> تا زمان ثبت keystore واقعی، شناسه بسته و شناسه محصول، workflow انتشار عمداً متوقف می‌ماند. کنترل کیفیت عادی مستقل از این اطلاعات قابل اجراست.
